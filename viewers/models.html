Wire format and payload models

Wire & payload models

The CBOR wire format is specified in CDDL (IETF RFC 8610). Payload models are derived mechanically from the WHO SMART FHIR logical models into a JSON-LD context, SHACL shapes and CDDL rules. Every example below is the Hepatitis B birth-dose certificate from smart-trust PR 129, which CI validates against all of these.

CDDL: HCERT envelope

api/cddl/hcert.cddl
; HCERT wire format (CBOR), RFC 8610 CDDL.
;
; Sources (WHO SMART Trust IG):
;   hcert_spec.md 3.2 CWT Claims, 4.2 Barcode          (deployed)
;   qr_code_generation.md 4-9 Steps 3-8                (PR 129)
;   RFC 9052 COSE_Sign1, RFC 8392 CWT
;
; Payload rules (dvc-min, ...) are generated from the FHIR logical models
; into models/generated/<ig>.cddl. CDDL has no import mechanism, so this file
; is concatenated with them for validation (tools/check-models/check_models.py).
;
; Draft for upstreaming: the envelope belongs in WorldHealthOrganization/
; smart-trust and the payload rules with their logical models (OI-19).

; Steps 5-8 output, before ZLIB/Base45. Issuers MUST tag. [STT-COS-001]
hc1-cose = #6.18(cose-sign1)

cose-sign1 = [
  protected: bstr .cbor protected-header,
  unprotected: unprotected-header,
  payload: bstr .cbor cwt-claims,
  signature: bstr,
]

; alg and kid in the protected header. [STT-COS-003]
protected-header = {
  1 => cose-alg,
  ? 4 => kid,
}

; kid MAY appear here instead; the protected one wins. [STT-COS-003]
unprotected-header = {
  ? 4 => kid,
}

cose-alg = es256 / ps256
es256 = -7    ; primary   [STT-COS-002]
ps256 = -37   ; secondary [STT-COS-002]

; First 8 bytes of SHA-256 over the DER DSC. [STT-KID-001]
kid = bstr .size 8

; ES256 signatures are fixed-width r||s. [STT-COS-005]
es256-signature = bstr .size 64

; CWT claim set. [STT-CWT-001]
cwt-claims = {
  ? 1 => tstr,             ; iss, alpha-2 when a country [STT-CWT-005]
  6 => numeric-date,       ; iat [STT-CWT-002]
  4 => numeric-date,       ; exp, mandatory [STT-CWT-003]
  -260 => hcert,
}

; HCERT requires integer NumericDate (RFC 8392 would also allow float).
numeric-date = int

; Issuance: exactly one subclaim entry, so hcert is a choice of
; single-entry maps. [STT-SEL-004] (OI-02)
; Subclaim registry (QR Code Generation 2.1). [STT-SEL-001]
; Adding a subclaim means adding an alternative here.
hcert = hcert-dcc / hcert-ddcc-vs / hcert-ddcc-tr / hcert-vhl / hcert-dvc / hcert-mtl

hcert-dcc = { 1 => any }               ; HCertDCC (EU DCC core data set)
hcert-ddcc-vs = { 3 => any }           ; DDCCCoreDataSetVS (proposed)
hcert-ddcc-tr = { 4 => any }           ; DDCCCoreDataSetTR (proposed)
hcert-vhl = { 5 => vhl-payload / vhl-uri } ; Verifiable Health Link [STT-VHL-002]
hcert-dvc = { -6 => dvc-min }          ; DVCMin, development range (OI-09, OI-17)
hcert-mtl = { -7 => any }              ; MedicationTreatmentLineMin, development range

; The SMART Health Links payload format that IHE VHL reuses, as a CBOR map:
; the primary form at key 5. [STT-VHL-001, STT-VHL-002] (OI-21, OI-23)
vhl-payload = {
  url: tstr,               ; https manifest URL (a FHIR List search)
  key: tstr .size 43,      ; 32 random bytes, base64url
  ? exp: int,              ; epoch seconds
  ? flag: tstr .regexp "L?P?",
  ? label: tstr .size (0..80),
  ? v: int,
  ? extension: { ? fhirBaseUrl: tstr, * tstr => any },
}

; IHE ITI-YY3's text form, still accepted on decode. [STT-VHL-003]
vhl-uri = tstr .regexp "vhlink:/[A-Za-z0-9_-]+"

; Context identifier and Base45 text (step 8). [STT-HC1-001, STT-B45-001]
hc1-string = tstr .regexp "HC1:[0-9A-Z $%*+./:-]+"

CDDL: payload rules, generated from the logical models

models/generated/trust-phw.cddl
; Generated by tools/lm-derive/lm_derive.py from FHIR logical models. Do not edit.
; Wire (CBOR) encoding of the payload logical models. Element names are
; the logical-model element names; primitive types carry the FHIR R5
; regex (RFC 8610 .regexp: XSD regex, implicitly anchored).

; http://smart.who.int/trust-phw/StructureDefinition/DVCMin (abstract)
dvc-min = {
  n: fhir-string,
  dob: fhir-date,
  s: fhir-code,  ; binding extensible http://hl7.org/fhir/administrative-gender
  nt: fhir-code,  ; binding extensible http://hl7.org/fhir/ValueSet/iso3166-1-3
  ? id: fhir-string,
  ? dt: fhir-code,  ; binding extensible http://terminology.hl7.org/ValueSet/v2-0203
  ? gn: fhir-string,
  vx: dvc-min-vaccine-details,
  v: fhir-string
}

; http://smart.who.int/trust-phw/StructureDefinition/DVCMinPreQual
dvc-min-pre-qual = {
  n: fhir-string,
  dob: fhir-date,
  s: fhir-code,  ; binding extensible http://hl7.org/fhir/administrative-gender
  nt: fhir-code,  ; binding extensible http://hl7.org/fhir/ValueSet/iso3166-1-3
  ? id: fhir-string,
  ? dt: fhir-code,  ; binding extensible http://terminology.hl7.org/ValueSet/v2-0203
  ? gn: fhir-string,
  vx: dvc-min-vaccine-details-pre-qual,
  v: fhir-string
}

; http://smart.who.int/trust-phw/StructureDefinition/DVCMinVaccineDetails (abstract)
dvc-min-vaccine-details = {
  vp: fhir-code,
  dv: fhir-date,
  bo: fhir-string,
  (is: fhir-id, ? cn: fhir-string // ? is: fhir-id, cn: fhir-string)  ; must-have-issuer-or-clinician-name
}

; http://smart.who.int/trust-phw/StructureDefinition/DVCMinVaccineDetailsPreQual
dvc-min-vaccine-details-pre-qual = {
  vp: fhir-code,  ; binding required http://smart.who.int/pcmt-vaxprequal/ValueSet/PreQualProductIds
  dv: fhir-date,
  bo: fhir-string,
  (is: fhir-id, ? cn: fhir-string // ? is: fhir-id, cn: fhir-string)  ; must-have-issuer-or-clinician-name
}

; FHIR R5 primitive types (hl7.fhir.r5.core#5.0.0)
fhir-code = tstr .regexp "[^\\s]+( [^\\s]+)*"
fhir-date = tstr .regexp "([0-9]([0-9]([0-9][1-9]|[1-9]0)|[1-9]00)|[1-9]000)(-(0[1-9]|1[0-2])(-(0[1-9]|[1-2][0-9]|3[0-1]))?)?"
fhir-id = tstr .regexp "[A-Za-z0-9\\-\\.]{1,64}"
fhir-string = tstr .regexp "[\\s\\S]+"
